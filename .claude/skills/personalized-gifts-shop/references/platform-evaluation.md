# בחירת פלטפורמה וסליקה

## עיקרון
בוחרים את הפתרון **הפשוט ביותר שעובר את כל מבחני הקבלה הקשים**. פלטפורמה מנוהלת עם יכולות מובנות עדיפה על קוד מותאם, כל עוד היא עומדת בדרישות. קוד מותאם נבחר רק אם החלופות המנוהלות נכשלו בבדיקה המעשית.

## מבחני קבלה (חובה)
| # | מבחן | איך בודקים |
| --- | --- | --- |
| 1 | שדות התאמה לכל מוצר (טקסט/תמונה, חובה/רשות, הגבלת תווים), ובעלת העסק עורכת אותם בלי קוד | יוצרים 2 מוצרים עם שדות שונים |
| 2 | העלאת תמונה מהטלפון כולל HEIC, עם תצוגה מקדימה והחלפה | העלאה מאייפון ומאנדרואיד |
| 3 | שתי יחידות מאותו מוצר עם תמונות שונות מופיעות כשתי שורות נפרדות בהזמנה | הזמנת בדיקה |
| 4 | מארז שבו לכל פריט התאמה ותמונה משלו, וכל אחת מגיעה מקושרת לפריט הנכון בהזמנה | הזמנת בדיקה עם מארז של 2 פריטים |
| 5 | הקבצים לא נגישים לציבור, ובעלת העסק מורידה את הקובץ המקורי | פותחים את קישור הקובץ בחלון גלישה בסתר |
| 6 | עברית ו־RTL מלאים: חנות, קופה, הודעות מייל וניהול | בודקים מסך אחרי מסך |
| 7 | סליקה ישראלית (כרטיס אשראי בשקלים, ותשלומים אם רלוונטי) | תשלום במצב בדיקה |
| 8 | עריכת ההתאמות מהסל בלי להתחיל מחדש | בודקים בסל |

## מבחנים חשובים (שוקלים)
- עלות חודשית כוללת: פלטפורמה + תוספים + עמלות סליקה.
- עומס תחזוקה: עדכונים, אבטחה, גיבויים. מי אחראי לכל אחד מהם?
- מספר התוספים החיצוניים שצריך. כל תוסף הוא עוד נקודת כשל ועוד מנוי.
- ייצוא נתונים, והאם אפשר לעזוב את הפלטפורמה בלי לאבד מוצרים והזמנות.
- הפקת חשבונית או קבלה אוטומטית (לפי סוג העוסק).
- נוחות ניהול מהטלפון.

## חלופות לבדיקה
**את הרשימה הזו לא מקבלים כעובדה.** בודקים בתיעוד העדכני מה כל חלופה תומכת בו היום ובאיזה מחיר.

1. **פלטפורמת חנות מנוהלת + תוסף התאמה אישית** (למשל Shopify, Wix, או פלטפורמה ישראלית).
   - יתרונות: אחסון, אבטחה וסליקה מנוהלים. התחזוקה נמוכה.
   - לבדוק: האם תוסף ההתאמה תומך במבחנים 3 ו־4 (בעיקר התאמה לכל פריט בתוך מארז). איפה נשמרים הקבצים והאם הם פרטיים. איזו סליקה ישראלית נתמכת ובאיזו עמלה. האם התוספים בעברית.
2. **WordPress + WooCommerce + תוספים** (התאמה אישית, מארזים, סליקה ישראלית).
   - יתרונות: גמישות רבה ותוספים ישראליים לסליקה ולחשבוניות.
   - חסרונות: אחסון, עדכונים ואבטחה באחריות העסק, ותוספים עלולים להתנגש זה בזה. התחזוקה בינונית עד גבוהה.
3. **בנייה מותאמת** (למשל Next.js + Supabase עם Auth, Postgres ו־Storage פרטי + ספק סליקה ישראלי).
   - יתרונות: שליטה מלאה במבחנים 3–5. אין עמלת פלטפורמה.
   - חסרונות: הכי הרבה עבודה ותחזוקה. ממשק הניהול נבנה מאפס. נבחרת רק אם 1 ו־2 נכשלו במבחן קריטי.

### ספקי סליקה
לבדוק מול התיעוד העדכני: התאמה לפלטפורמה שנבחרה, עמלות, דמי חודש, תשלומים, Bit/Apple Pay/Google Pay, הפקת חשבוניות, והאם יש סביבת בדיקה (sandbox). את ההשוואה רושמים ב־`docs/decisions.md`.

## בדיקה מעשית לפני התחייבות
1. פותחים חשבון ניסיון או סביבה חינמית. **לא משלמים בלי אישור.**
2. בונים מינימום: כוס עם שדה שם ותמונת חובה, מגבת עם שדה טקסט, ומארז שמכיל את שתיהן.
3. מריצים את תרחישים 3 ו־4 מתוך `test-scenarios.md`.
4. בודקים את ההזמנה שנוצרה בצד הניהול: האם ברור איזו תמונה שייכת לאיזה פריט?
5. רושמים את התוצאות: עבר, נכשל, או עבר עם עקיפה (ואיזו).
